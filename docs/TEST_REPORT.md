### 冷启动与认证修复的证据边界

开始时只读 health 为 `ready_for_task=true`、`runtime_ready=false`，认证尚未验证；诊断不启动 worker。任务启动后使用应用内置运行时创建本项目自有 worker，不要求桌面先创建 sidecar。原生字段经临时私有 Unix socket 握手，使用应用现有密钥辅助函数且 `createIfMissing=false`；不读取裸 token、不关闭静态加密、不导出凭证、不重写账号。

早期 standalone 短请求返回 `Authentication required`，外层 stopReason 为 refusal；这是认证问题，不能据此称内容被安全策略拒绝。另一些早期模型目录失败发生在 prompt 提交之前，没有创建模型生成任务。随后补齐原生受保护字段及应用产品元数据，初始化后再选择模型，双模型真实短任务成功。应用产品缓存路径仍可能晚于初始模型/工具快照解析，进一步由原生 launcher 在 CLI 初始化前只读加载现有缓存，内联投影到该自有进程环境；明确 Bash allow_once 的补充任务通过，不改写用户缓存。模型任务成功与用户页面积分核对是两项证据；本轮新路径已有七条 2.88 积分的独立核对，未覆盖请求仍保持未知，不能沿用旧四次任务的 2.26 积分结论。

## 修复的错误

原版 `test_legacy_session_can_be_adopted_from_its_persisted_prompt` 在 macOS 失败。同一个文件的路径可能分别表示为 `/var/...` 和 `/private/var/...`；上游采用字符串包含判断，误认为记录没有提到目标文件。

补丁核对路径别名的实际解析，并检查文件名边界。新增回归覆盖：别名与空格路径、同名前缀但不同文件、不同父目录。上游参考代码保持原样，补丁只在测试临时副本应用。

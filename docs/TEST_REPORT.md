## 修复的错误

原版 `test_legacy_session_can_be_adopted_from_its_persisted_prompt` 在 macOS 失败。同一个文件的路径可能分别表示为 `/var/...` 和 `/private/var/...`；上游采用字符串包含判断，误认为记录没有提到目标文件。

补丁核对路径别名的实际解析，并检查文件名边界。新增回归覆盖：别名与空格路径、同名前缀但不同文件、不同父目录。上游参考代码保持原样，补丁只在测试临时副本应用。

## 依赖与安装观察

依赖已固定在 `requirements-test.lock`。本机安装时，`cryptography 50.0.2` 从源码构建 Intel wheel 成功；这可能要求额外编译工具，不能据此声称将来的安装过程完全免编译。正式发布需要检查 Intel 二进制依赖可用性或提供打包运行时。

### 真正修复的 Mac 启动差异

桌面应用不提供完整 TUI bundle。启动必须显式设置 `CODEBUDDY_FORCE_LITE_WB_BUNDLE=1`，并使用 Electron 兼容的应用入口。采用 `port=0` 让应用完成端口就绪与凭证传递；创建请求等待预算为 200 秒，避免冷启动时误报失败。

### 当前未确认

- 用户在 WorkBuddy 账号/额度页面核对订阅用量。
- 当前 Codex 桌面界面重新加载 MCP 后的显示与调用，需要用户在重新加载后确认；底层配置识别和真实 stdio 调用已经通过。
- 用户整个 WorkBuddy 应用退出的真实场景未执行，当前只验证自己的 worker 失联；其他用户 socket、不兼容版本和协议通过隔离模拟覆盖。
- 原生桌面历史/专家/旧会话继承属于后续能力；本版本没有直接写应用数据库。

启动接口支持可选 `request_id`，相同标识与相同输入返回原任务，重启及记录损坏时不会重复提交模型。新增 6 项回归覆盖重试、冲突、重启和记录损坏。

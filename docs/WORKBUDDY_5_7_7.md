## 原生接口与版本边界

5.7.7 的保护模块路径仍为 `main/process-cpu-sampler.js`，导出名称改成压缩短名。原具名导出在本机均为 `undefined`，新导出均为函数；源码审计核对了各函数用途。

| 5.6.2 / 桥接功能名称 | 5.7.7 导出 |
| --- | --- |
| `init_dist` | `$` |
| `normalizeAtRestBuildKeyCapabilities` | `_t` |
| `keyblobPathFor` | `tt` |
| `loadOrCreateKeyblobMasterKey` | `nt` |
| `encodeAtRestEncryptionBootstrap` | `Z` |
| `disposeAtRestEncryptionBootstrap` | `X` |

launcher 按精确版本选择映射，确认全部导出为函数后才继续。保留应用原生 storage binding、`createIfMissing=false`、`fields` 加密、私有 credential/ready socket 身份校验和密钥清零。sidecar 协议仍为 6；CLI 入口、loopback ACP 路径与既有契约一致。静态审计与函数存在检查本身不等于真实任务验收。

开发清单包含 5.6.2、5.7.7；5.7.6 未验收，不加入。未知版本仍默认拒绝，Intel 架构检查保留。5.6.2 为历史基线，本次没有降级重跑其桌面实测；本机新的 5.7.7 验收范围见下文。

## 产品缓存与模型就绪门槛

5.7.7 CLI 会先读另一份 localStorage 产品缓存，再异步合并 GUI 产品配置。普通 ACP 的初始模型目录被固定，后来更新产品配置可能仍不广告新模型。本机产品 snapshot 中确认 Step 的准确 ID 为 `step-5-preview`。

自有 5.7.7 worker 设置 `CODEBUDDY_DISABLE_PRODUCT_CACHE=1`，跳过这次旧缓存读取，并继续在应用进程中只读加载 GUI 的 `acc-product-config-v3.json`，初始化 CLI 前内联投影。该开关仅跳过读取；应用常规同步、保存缓存行为仍存在，不能称为“CLI 完全不写缓存”。Python 不读取缓存正文，桥接不删除或改写缓存。

GUI 重开时还会先发布基础模型配置。新增启动门槛要求指定模型同时出现在产品 `models` 与 `cli` agent 的模型列表中，再冻结本次投影并加载 CLI；等待有期限，不替换指定模型、不自动重发 prompt。另将已经连接的保护握手响应等待从 2 秒调整为有上限的 10 秒；应用自身验证及 20 秒连接重试期限保留。以实际恢复任务成功验证修复效果，不只依赖这两个配置。

## Step 额外请求的限制

额外 Step 取消测试在任何模型正文输出前失败：`model_output_started=false`、`status=failed`、`stop_reason=refusal`。对应自有原生历史与专用日志确认服务返回 **HTTP 429、错误码 6021、`queue.full.title`（队列满）**，随后应用映射为 ACP `refusal`。

这里的 `refusal` 不足以认定内容政策拒绝或认证失败；本次精确错误是服务队列容量问题。该任务最终清理确认，但未进入“正文输出后取消”的阶段，**Step 取消能力未由此验证**，没有自动重发。

## 清理状态后台刷新

管理器查询终态且待清理的任务时，在后台安排自有运行时恢复。状态/结果查询与等待不执行同步恢复；同一任务保留并发去重及两秒节流。只更新清理字段，保留原终态、错误与部分结果，不重新提交模型请求。

关闭后停止排程并阻止晚到结果写回；已启动恢复未结束时保留实例锁。合成回归覆盖慢恢复、同任务并发查询、异常脱敏及节流后重试、关闭期间的回写保护与实例锁交接。相关回归包含 40 项管理器测试；最终完整项目测试 223 项通过。

## 剩余边界

- Step 额外取消测试因队列满未进入取消阶段；Step 文本和 1m 设置成功不代表它的取消已单独验证。
- 本次没有重跑三个模型的 MCP 业务调用；旧 5.6.2 的 scansci-pdf 成功、sheetagent 依赖错误及桌面连接器限制仍为历史证据，不改称 5.7.7 新验收。工具详情待办 #11、连接器待办 #5 保持开放。
- 本轮计费未核对。Step 的免费体验标签不能代替账号用量页的实际扣费记录。
- 本次开发代码使用独立 stdio MCP 验收；当前 Codex 对话已运行的原生服务可能仍是旧代码。需要完全重启 Codex，再只读确认 `bridge_version=0.1.1`。这一步不能以独立验收替代。
- 5.7.6、Apple Silicon、未知 WorkBuddy 版本仍不在支持范围。私有接口未来更新仍需适配。

## 当前启动与认证边界

- WorkBuddy GUI 已登录但没有 sidecar 时，桥接器能够在任务启动时创建自己的运行时。只读 `health` 不启动 worker，返回 `ready_for_task=true` 只表示安装、版本和 GUI 条件满足；未运行时的 `authenticated=null` 表示尚未验证。
- 自有运行时通过临时私有 Unix socket 完成原生字段握手，并使用应用现有密钥辅助函数读取受保护登录配置；`createIfMissing=false`。不读取或输出裸 token、不关闭静态加密、不导出凭证，也不重写账号。
- 两种主力模型已在新路径完成短任务和 1m 会话预算验证。成功任务证明该执行路径能够完成云端认证；新任务积分归属与扣减仍需用户核对。此前四次暖启动任务的 2.26 积分确认不能代替这次核对。
- 桥接器保存自己的任务记录，不直接注册高层桌面历史，也不会自动继承任意专家或旧会话。目标桌面 MCP 尚未继承，见 [验收与差距](AUDIT.md)。
- WorkBuddy 更新后未知版本默认拒绝发出任务；先诊断、适配再更新支持表。依赖私有原生字段和密钥辅助函数意味着应用升级后仍需本机维护。

## 更新验证顺序

1. 记录应用版本、CPU 架构、GUI 身份和初始运行时是否存在。
2. 执行只读诊断；分别记录可启动条件、运行时就绪与认证状态。
3. 执行全部单元测试。
4. 在独立目录完成冷启动文本、文件、权限、取消、故障与 GUI 退出恢复验收；核对自有资源清理和请求幂等。
5. 按 [冷启动设计](COLD_START.md) 复核原生保护握手、产品配置投影及自有清理；核对新任务的账号用量，验证 Codex 原生 MCP 加载当前代码，再更新本表和发布说明。

alpha.2 已通过两种主力模型短任务与 1m 会话预算、find-skills 加载，以及已运行通道中的权限/取消/故障。用户核对四次任务共 2.26 积分，使用端显示 CLI。目标桌面 MCP 未继承。

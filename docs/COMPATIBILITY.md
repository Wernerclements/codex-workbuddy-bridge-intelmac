## 更新验证顺序

1. 记录应用版本与 CPU 架构。
2. 执行只读诊断，确认协议、实例和认证可用。
3. 执行全部单元测试。
4. 在独立任务目录完成真实任务、取消与文件结果验收。
5. 更新本表并保留脱敏测试报告后，才声明支持该版本。

## 当前边界

- 使用 WorkBuddy 应用内置运行时和用户配置目录；没有新配模型 API。用户已核对两种主力模型的账号用量，四次任务合计 2.26 积分，使用端显示 CLI。
- 桥接器保存自己的任务记录；没有外接高层桌面会话注册，也不会自动继承任意专家或旧会话。
- 已真实正常退出整个 WorkBuddy 应用并确认旧 sidecar 消失；原任务不重发。重新打开后的冷启动通道未自动建立，完整恢复未通过。
- WorkBuddy 更新后未知版本默认拒绝发出任务；先诊断、适配再更新支持表。

## 整应用退出验收结果

WorkBuddy 5.6.2 的退出/恢复脚本已完成默认预览和三项保护回归，本机自动测试共152项通过。真实退出已执行，正常退出与原任务不重发通过；重开后的通道恢复超时。界面已登录正常与内部sidecar/CLI Host可用是不同条件。

Codex完全重启后的原生health已通过；该结果发生在WorkBuddy退出测试前，不证明之后冷启动端点恢复。测试结束时WorkBuddy GUI已重开并由用户确认正常登录，没有旧测试worker遗留。
